## 1. 目的とスコープ

選択中組織のレコードを**オブジェクト単位でバックアップ**し、**バックアップから復元**する独立ウィンドウ（2 タブ）を追加する。バックアップはローカル（`data\backups\`）に保存し、ラベル・説明・組織情報・件数付きで一覧管理する。

### 1.1 確定事項（2026-10-04 ユーザー確認済み）

- ウィンドウ構成 = **1 ウィンドウ + 2 タブ（バックアップ / 復元）**、入口は**メイン上部バーのアイコン**
- バックアップのエンジン = **REST（既定・JSON 保存）+ 大量レコード時は Bulk API（CSV）に自動切替**（閾値は設定 `backupRestMaxRecords`・既定 2,000）
- バックアップ対象オブジェクトの**選択を記憶**（組織単位・次回起動時に復元）
- ラベル・説明 = 編集可。既定は **ラベル = 日時**、**説明 = 組織情報（表示名 / ユーザー名 / OrgId）**
- オブジェクト一覧の**件数はバックグラウンドで順次取得 + ローカルキャッシュ**
- 復元は**照合方式**（下記 1.2）+ 既存一致時の **スキップ（既定）/ 上書き** を画面で切替
- 復元タブ: バックアップ選択 → オブジェクト一覧（件数・エンジン）+ **レコード詳細ボタン（別ウィンドウ）** + 復元対象の選択
- **検索機能** = バックアップ一覧 / オブジェクト一覧（両タブ）/ レコード詳細ウィンドウ（すべて AND・スペース区切り）

### 1.2 復元の照合方式（実 API 調査を踏まえた確定仕様）

**【実測 2026-10-04】Salesforce は Id を指定した挿入を全面拒否する:**
- REST `POST /sobjects`（Id 入り）→ `INVALID_FIELD_FOR_INSERT_UPDATE`（400）
- Bulk API 2.0（Id 列付き CSV）→ `cannot specify Id in an insert call`
- SOAP API `create()`（18 桁 Id）→ 同上（旧仕様は現行 API で無効）
- `sf data create record -v "Id=..."` → Id を無視して新規作成（使用しない）

したがって復元は次の方式とする（画面の「照合」コンボで制御・既定 = 自動）:

| 照合 | 条件 | レコードの扱い |
|---|---|---|
| **Id（自動: バックアップの OrgId = 対象組織の OrgId）** | 対象 Id が**存在**（queryAll で非削除） | **スキップ**（既定）/ **上書き**（Updateable 項目を PATCH） |
| | 対象 Id が**削除済み**（ごみ箱内） | **SOAP API undelete で復元 = Id 維持**。失敗時は新規挿入へフォールバック |
| | 対象 Id が**存在しない** | **新規挿入**（Id は新しい値） |
| **キー（自動: 別組織 / 手動で「キーで照合」を選択）** | キー項目（既定 = `Name`。オブジェクトごとに変更可）が一致する既存レコードあり | **スキップ** / **上書き**（一致レコードを PATCH） |
| | 一致なし | **新規挿入**（Id は新しい値） |

- **参照の自動張り替え**: 新規挿入されたレコードへの参照（describe の `Type = reference` 項目）は、**旧 Id → 解決先 Id**（既存一致 / undelete / 新規挿入のいずれか）に書き換える。マップに無い参照値はそのまま送信（相手が現存すれば成功、無ければエラーとして結果表示）
- 制限: 同一オブジェクト内の**後続レコードへの自己参照**は張り替え不可（新規挿入された場合のみ・エラー表示）。ごみ箱保持期間（15 日）を過ぎた削除済みレコードは新規挿入になる

### 1.3 含まないもの

- 元 Id の維持（API 制約・1.2 参照。Id 維持は undelete が可能な場合のみ）
- 添付・ContentVersion などバイナリ本体の復元（レコードとしての ContentVersion は対象外）
- スケジュール実行 / 外部ストレージへの保存
- オブジェクト間の順序制御 UI（参照張り替えで吸収。挿入は選択順）

## 3. 詳細仕様

### 3.1 保存形式（`data\backups\`）

- `data\backups\<yyyyMMdd-HHmmss>\metadata.json` — ラベル / 説明 / 作成日時 / OrgId / ユーザー名 / アプリバージョン / オブジェクト一覧（ラベル・件数・エンジン・ファイル名）
- 同フォルダにオブジェクトごとのデータ: `<Object>.json`（REST・全項目のレコード配列。`attributes` は除去）/ `<Object>.csv`（Bulk 2.0 の出力そのまま）
- `data\backups\counts.json` — 件数キャッシュ（組織キー → オブジェクト → 件数 + fetchedAt）
- `data\backup-state.json` — バックアップタブの選択記憶（組織キー → 選択オブジェクト API 名の配列）

### 3.2 バックアップ処理

1. 選択オブジェクトの describe（`SObjectDescribeService`）から**全項目の SOQL** を構築（address / location などの複合項目は除外）→ 取得（件数 ≤ `backupRestMaxRecords` は REST JSON、超は `sf data export bulk` CSV）
2. 進捗（オブジェクト n/m・フェーズ）とキャンセル対応。失敗オブジェクトはメタデータに記録して継続
3. 完了後、復元タブのバックアップ一覧に即時反映

### 3.3 復元処理

1. バックアップの metadata を読み込み、対象組織の OrgId と比較して照合方式を決定（自動時）
2. オブジェクトごとに: レコード読み込み（JSON / CSV）→ describe で挿入可能項目のみに整形（Id・数式・作成日時系は除外）→ 1.2 の照合（queryAll で存在/削除判定・キー検索 / SOAP undelete）→ 新規挿入は REST composite（200 件/バッチ）or Bulk CSV（一時ファイル + `sf data import bulk`）
3. **参照張り替え**: 解決済みマップ（旧 Id → 既存/undelete の Id or 新規 Id）で `Type = reference` 項目を書き換え（Bulk 経路は CSV を読み込み書き換えて一時 CSV を再生成）
4. 結果 = オブジェクト別に 成功 / スキップ / 失敗（+ スキップ/失敗の内訳サンプル）。実行前確認ダイアログ（危険操作ポリシー連動）

### 3.4 件数（バックグラウンド取得）

- ウィンドウを開くと一覧を先に表示し、`SELECT COUNT() FROM X` を並列 4 で順次実行（進捗 n/m）。結果は `counts.json` に保存（組織単位）
- 既存キャッシュがあるオブジェクトは即時表示。「件数再取得」ボタンで全再取得

### 3.5 レコード詳細ウィンドウ（復元タブから）

- バックアップの `<Object>.json / .csv` を読み込み、**全項目テーブル**を別ウィンドウで表示
- 200 件 / ページ（最初へ / 前へ / 次へ / 最後へ）+ 検索（行内容の AND・スペース区切り）
- 読み込み上限 20,000 件（超過時は注記）

### 3.6 設定追加（settings.json）

- `backupRestMaxRecords`（既定 2,000）— これを超えるオブジェクトは Bulk API でバックアップ（復元も同経路）

## 7. 追補（2026-10-04）: ラベル/説明の自動入力・選択クリア・バックアップ比較タブ

### 7.1 ラベル / 説明の自動入力

- ウィンドウを開いた時点で既定値を入力しておく（クリアして実行した場合は実行時に再生成）
  - ラベル: `{組織エイリアス}_{yyyy-MM-dd_HH-mm}`（例: `acc_2026-10-04_13-47`。エイリアスが無い場合はユーザー名）
  - 説明: 1 行目 = エイリアス / 2 行目 = インスタンス URL / 3 行目 = `Org Id:`（または `組織 ID:`）/ 4 行目 = `Type:`（または `種類:` = 本番 / サンドボックス）
- 文言キー: `Backup_DefaultLabelFmt` / `Backup_DefaultDescFmt` / `Backup_OrgTypeSandbox` / `Backup_OrgTypeProduction`

### 7.2 選択のクリア

- バックアップ タブのツールバーに「選択をクリア」（`Backup_ClearSelection`）を追加。全解除して `backup-state.json` の記憶も空にする

### 7.3 バックアップ比較タブ

- 3 つ目のタブ「バックアップ比較」。左に **基準 (A)** と **比較対象 (B)** のバックアップ 2 覧（検索付き・開いた時に最新 2 件を自動選択）、右に比較結果グリッド
- 比較（`BackupCompareService`）: 両バックアップの `metadata.json` + レコード ファイルをオブジェクト単位に突合
  - レコードのキー = **Id**（無い行は全項目の内容で突合）
  - 値の比較はエンジン差を吸収: REST の型付き値と Bulk CSV の文字列、`null` ↔ 空文字、数値（`12.5` ↔ `12.50`）、真偽値、日時を正規化して一致判定
  - 差分 = **追加**（B のみ）/ **削除**（A のみ）/ **変更**（両方にあり値が異なる）。変更は項目名と `A の値 → B の値` を保持
- 結果グリッドの列: オブジェクト / ラベル / A 件数 / B 件数 / 追加 / 削除 / 変更 / 状態（一致・差分あり・A のみ・B のみ・エラー）+ 「↗」ボタン
- **変化のあるオブジェクトは行の色でハイライト**: 差分あり = 黄 / A のみ = 青 / B のみ = 紫 / エラー = 赤。「差分のあるオブジェクトのみ」チェックで絞り込み
- 「↗」で **レコード単位の比較結果を別ウィンドウ**（`BackupCompareRecordsWindow`）で表示: 状態（追加 / 削除 / 変更）+ Id + 表示名 + 変更内容（`項目: A → B` を最大 5 項目、超過は「… 他 n 項目」）。検索（AND）と 200 件/ページ、上限 20,000 件（注記付き）
- 進捗（n/m オブジェクト名）/ キャンセル対応。比較は読み取りのみで組織 API は呼ばない（ローカル ファイルのみ）

### 7.4 レコードページを開く列（2026-10-04 追記）

- レコード詳細ウィンドウと比較のレコード単位ウィンドウのテーブル先頭に「レコードページを開く」（↗）列を追加
- リンク先 = `{instanceUrl}/lightning/r/{Object}/{Id}/view`（`BackupOrgUrls.BuildRecordUrl`）。Id が無い行 / URL が解決できない場合はボタン無効
- インスタンス URL は `BackupOrgUrls.Resolve`: 1) 現在のウィンドウの組織（組織 ID / ユーザー名一致）→ 即時、2) ユーザー名で認証済み組織を検索、3) 組織 ID で検索（2・3 は必要なときだけ `sf org list`）
- 比較ウィンドウでは削除行 = A、追加 / 変更行 = B のレコードページを開く（無い場合は他方で代替）
